# Phase 3 Plan: Customer Self-Service & Account Recovery
# Customer Account & Login Management Enhancement

**Phase**: 03  
**Goal**: Complete the customer account lifecycle — from admin-controlled account creation through secure self-service password recovery and in-dashboard password changes — while adding full admin visibility and control over customer login status.  
**Depends on**: Phase 1 (complete), existing customer portal (920ebaf)  
**Requirements**: AUTH-01 (existing), AUTH-02 (new), AUTH-03 (partial), AUTH-04 (existing)

---

## Success Criteria

1. Admin can see the real login status (active / disabled / setup-pending / never-logged-in) of every customer from the Login Modal.
2. Admin can resend a setup/invitation link, send a password reset, and disable/enable a customer's login — without knowing the customer's password.
3. Customers can request a password reset email from the `/login` page via a "Forgot password?" link.
4. Customers can complete account setup / password recovery via a secure recovery email that lands on `/reset-password`.
5. Authenticated customers can change their own password from the `/dashboard/profile` page.
6. Zero regressions on: `/p/[slug]`, `/review/[slug]`, `/r/[cardCode]`, customer login, dashboard auth, portfolio/gallery, admin customer activation.

---

## Wave Structure

```
Wave 1 (Admin login management)     → No customer-visible changes
Wave 2 (Customer password recovery) → New pages, proxy update, Supabase config
Wave 3 (In-dashboard password change) → Dashboard profile enhancement
```

## Wave 1 — Admin Login Status & Management Actions

### Task 03-01: New Admin API — `GET /api/admin/customers/login-status`

**File**: `app/api/admin/customers/login-status/route.js` *(new)*  
**Auth**: `authenticateAdmin(request)` — admin cookie + Supabase token + `is_admin()` RPC  
**Input**: `?customer_id=<uuid>`  
**Output**:
```json
{
  "auth_user_id": "...",
  "email": "...",
  "email_confirmed_at": "ISO date or null",
  "last_sign_in_at": "ISO date or null",
  "banned_until": "ISO date or null",
  "is_banned": true | false,
  "setup_complete": true | false
}
```
**Implementation**:
- `serviceClient.auth.admin.getUserById(auth_user_id)` using `SUPABASE_SERVICE_ROLE_KEY`
- Never returns passwords, raw JWT, or service key
- Returns 404 if no `auth_user_id` on the customer

---

### Task 03-02: New Admin API — `POST /api/admin/customers/resend-setup`

**File**: `app/api/admin/customers/resend-setup/route.js` *(new)*  
**Auth**: Admin only  
**Input**: `{ customer_id: string }`  
**Action**:
- Fetch customer → get `auth_user_id`
- `serviceClient.auth.admin.generateLink({ type: "recovery", email: customer.email })`
- Return `{ action_link }` — admin copies/shares this link manually
**Security**: Link is single-use, Supabase-TTL-controlled. Never emailed automatically by this route.

---

### Task 03-03: New Admin API — `POST /api/admin/customers/send-password-reset`

**File**: `app/api/admin/customers/send-password-reset/route.js` *(new)*  
**Auth**: Admin only  
**Input**: `{ customer_id: string }`  
**Action**:
- Fetch customer → get linked email from `auth.admin.getUserById`
- `serviceClient.auth.admin.generateLink({ type: "recovery", email, options: { redirectTo: "https://nfcista.vercel.app/reset-password" } })`
- **Option A (safer for now)**: Return the link to admin → admin shares it with the customer
- **Option B (future)**: Trigger Supabase to send the email directly via `supabase.auth.resetPasswordForEmail`  
- **Decision**: Implement Option A first (no email infra dependency). Admin copies link and sends via WhatsApp/email.  
**Anti-enumeration**: Never reveal whether the email existed or not in the error message to non-admin callers (admin-only route, so this is acceptable).

---

### Task 03-04: New Admin API — `POST /api/admin/customers/toggle-login`

**File**: `app/api/admin/customers/toggle-login/route.js` *(new)*  
**Auth**: Admin only  
**Input**: `{ customer_id: string, action: "disable" | "enable" }`  
**Action**:
- Fetch customer row → get `auth_user_id`
- `disable`: `serviceClient.auth.admin.updateUserById(auth_user_id, { ban_duration: "876600h" })`
- `enable`: `serviceClient.auth.admin.updateUserById(auth_user_id, { ban_duration: "none" })`
- Returns updated status
**Security**: Only admin can call this. Does not delete auth account or customer profile.

---

### Task 03-05: Enhance Admin Login Modal — `app/admin/page.js`

**Scope**: Modify the Login Modal (`loginModalCustomer` state) to:

1. **On open when `auth_user_id` exists**: Fetch `GET /api/admin/customers/login-status` and display:
   - "✓ Active Login" (green) — signed in recently, not banned
   - "⚠ Login Disabled" (red) — banned_until is set
   - "📧 Setup Pending" (amber) — never signed in, email not confirmed
   - Last sign-in date/time
   - Email address

2. **New action buttons in the linked-login view**:
   - "Resend Setup Link" → calls `POST /api/admin/customers/resend-setup` → shows copyable link
   - "Send Password Reset" → calls `POST /api/admin/customers/send-password-reset` → shows copyable link
   - "Disable Login" / "Enable Login" → calls `POST /api/admin/customers/toggle-login`

3. **State additions** (local to component, no schema change):
   - `loginAuthStatus` — result from `login-status` API
   - `loginStatusLoading` — loading indicator for status fetch
   - `loginActionResult` — result from resend/reset/toggle actions

**Isolation guarantee**: No changes to customer list, customer table schema, portfolio, profile slug, or `is_active` field. All new actions are scoped to the Login Modal only.

## Wave 2 — Customer Password Recovery Pages

### Task 03-06: New Page — `app/forgot-password/page.js`

**Route**: `/forgot-password`  
**Auth**: Unauthenticated (public page)  
**UI**:
- Email input field
- "Send Reset Link" button
- On submit: `supabase.auth.resetPasswordForEmail(email, { redirectTo: "https://nfcista.vercel.app/reset-password" })`
- Always shows success message regardless of whether email exists (anti-enumeration)
- "Back to Login" link → `/login`

**Anti-enumeration**: The response is always "If this email is registered, you will receive a reset link." — never confirms/denies registration.

---

### Task 03-07: New Page — `app/reset-password/page.js`

**Route**: `/reset-password`  
**Auth**: Token-protected (query param `token_hash` from Supabase recovery email)  
**Flow**:
1. On mount: extract `token_hash` and `type` from URL search params
2. If `type === "recovery"` and `token_hash` exists: `supabase.auth.exchangeCodeForSession(token_hash)` — exchanges for a real session
3. Show new password + confirm password form
4. On submit: `supabase.auth.updateUser({ password: newPassword })`
5. On success: clear session (or keep), redirect to `/login` with success message
6. If no valid token: show "Invalid or expired link" with link back to `/forgot-password`

**Security**: Token exchange is done via Supabase SDK — Supabase validates the token server-side. The app never handles raw JWTs.

## Wave 3 — Customer In-Dashboard Password Change

### Task 03-11: Add "Change Password" Section — `app/dashboard/profile/page.js`

**Scope**: Add a new "Security" section at the bottom of the Edit Profile page.  
**UI**:
- "Current Password" field (required for verification — Supabase `updateUser` with password requires an active session)
- "New Password" field (min 8 characters)
- "Confirm New Password" field
- "Update Password" button

**Implementation**:
```js
const { error } = await supabase.auth.updateUser({ password: newPassword });
```
- Supabase validates the session before accepting the update
- No API route needed — this is a direct Supabase client SDK call from the browser
- On success: clear the form fields, show success toast
- On error: show the Supabase error message

**Security**: `supabase.auth.updateUser()` only works with a valid authenticated session. The customer must be logged in. No server-side code needed; Supabase handles validation.
